# Agent notes

More rules live in `.agents/rules/` and workflows in `.agents/workflows/`.

## Scripts

- `bash .agents/scripts/run_suites.sh [--only a,b]`: the quick regression suites (bspwalk selftest, fixtures and eye cache, lmoptimizer, proplm, vvis sight-line and mergeflow) against the binaries in `game/bin/x64`, one pass/fail line each. Run it after a merge or a rebuild. `bspwalk_cache` (`game/bin/x64/unit_test/bspwalk/run_bspwalk_cache_tests.py`) reads the fixture BSPs `bspwalk_fixtures` compiles: it runs `-eyeverify` on each, and requires the same tiers at the default eye cache, `-eyecache 1` and `-threads 4` on four of them; run it after any change to the eye store or the tile generator (`bw_eyestore.cpp`, `bw_eyes.cpp`).
- `python -I .agents/scripts/proplm_rebake_ab.py [--vbsp A.exe --vbsp B.exe] [--keep DIR] model...`: compiles the staticpropbounce fixture with one `proplm "rebake"` prop per model and prints the rebake log lines and the pak files it added (sizes, CRC); with two VBSP builds it diffs the pak lumps. A second build must sit in `game/bin/x64` (it needs the DLLs beside it).
- `bash .agents/scripts/worktree_build_setup.sh [--build] [--project <name>]...`: makes a fresh git worktree buildable (copies the untracked libs, runtime DLLs and test maps from the main checkout, generates the projects, fixes the solution name), then builds the whole solution or only `src/utils/<name>`. Run it first in any new worktree, and again after a `.vpc` changes.
- `bash .agents/scripts/review_extract.sh <out_dir> <base> <head> <regex>...`: a small two-commit repo of just the files a third-party review needs. Point `review_fast` / `review_final` at it (`diff_range xbase..xhead`); the full repository snapshot is too large to launch.
- `python game/bin/x64/prop_corpus_check.py --game <dir>`: feeds every model the game mounts through VBSP's `prop_static` path and lists the ones it refuses, with the reason. Run it after any change to the model checks (`Proplm_ValidateMdl`, `Proplm_LoadVvdVertices`, `LoadStudioModel`); about 15 seconds for stock HL2 content.
- `python -I .agents/scripts/proplm_ppl_ab.py --game <dir> --out <dir> --vrad old=<bin dir> --vrad new=<bin dir> [--lights 3000] [--coverage] model[:plain]...`: compiles the staticpropbounce fixture once, runs each VRAD build on it with `-StaticPropLighting`, and compares the per-texel prop lightmaps (`texelslighting_N.ppl`): texels lit only in one build, difference on the common ones, and (labelling one build twice) the run-to-run noise floor; `--coverage` re-derives VRAD's lit-texel counts from the rebaked model. Needs numpy. Use it for any change under the per-texel prop lighting in `vradstaticprops.cpp`.
- `python -I .agents/scripts/renamed_model_check.py --sdk <SDK root> --source-vpk <vpk> --out <dir> --vbsp base=<exe> --vbsp new=<exe> --vrad old=<bin dir> --vrad new=<bin dir> [--layout original]`: builds a scratch copy of the SDK's hl2mp game dir (junctions, hardlinks, nothing written to the install) holding one stock static prop copied byte for byte under another file name, then reports every VBSP and VRAD build's exit code and message on it (`--layout original` is the control with the file name unchanged).
- `python -I .agents/scripts/proplm_stale_vtf_check.py --game <dir> --out <dir> --vbsp base=<exe> --vbsp new=<exe>`: seeds a two-`proplm "1"`-prop map through VBSP and VRAD, then drops props from the VMF and recompiles with `-onlyents` (and `-keepstalezip`), listing the `materials/maps/<map>/proplm/<id>.vtf` pak entries before and after.
- `python -I .agents/scripts/vvis_pvs_compare.py --maps <dir> --out <dir> --run base=<bin dir> --run new=<bin dir>[,args]`: runs vvis builds (or edited portal files, `label=<bin dir>@<prt dir>`) on copies of the same BSP+PRT pairs and says whether the visibility lump is byte-identical, listing the cluster pairs gained and lost when it is not. Use it for any change under `src/utils/vvis`.
- `python -I .agents/scripts/make_corridor_prt.py <out_dir> <clusters>`: a synthetic straight-corridor portal file for a portal chain of a known depth (vvis's depth check).
- `python -I .agents/scripts/bspwalk_tier_diff.py base.json other.json...`, or `--bsp <map> --game <dir> --out <dir> --run base=<bin dir> --run new=<bin dir>[,arg...]`: diffs bspwalk face tiers between `-out` files, or runs several builds or argument sets on one BSP and diffs them (faces hidden in one run only, eye spacing and sample count, stage times, peak memory). `--same` exits 2 unless the tiers match. Use it for any change to the eye volume or the tier B passes (`bw_eyes.cpp`, `bw_vis.cpp`).

## Testing tools

Always pass `-game <dir>` when running any tool here (vbsp_lmo, vvis_optix, vrad, bspwalk) in a test, harness or script. Without it the tools fall back to the `VPROJECT` environment variable, which on a dev box can point at an unrelated game. The result is missing models or a vphysics.dll load failure that looks like a DLL problem. The bspwalk fixture harness's default game is set in `game/bin/x64/unit_test/bspwalk/run_bspwalk_tests.py` (`--game`).
